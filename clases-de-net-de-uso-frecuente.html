    5. Clases de .NET de uso frecuente

    Aquí presentamos algunas clases de uso frecuente de la plataforma .NET: cadenas, arreglos, colecciones, archivos y expresiones regulares. También trataremos LINQ (Language Integrated Query), que el curso de 2008 omitía aunque ya estaba disponible desde C# 3: hoy es la forma más común de manipular colecciones en C#. Antes, veremos cómo encontrar información sobre las miles de clases disponibles. Esta guía es indispensable para cualquier desarrollador de C#, incluso con experiencia.

    Los ejemplos de este capítulo, con excepción de la aplicación de ejemplo del final, son aplicaciones de un solo archivo ejecutadas con [dotnet run file.cs]. Se encuentran en la carpeta [05-classes-dotnet] del código del curso y se ejecutan con la configuración regional francesa (fr-FR), salvo los ejemplos de LINQ y de expresiones regulares, que se ejecutan con la configuración regional del inglés estadounidense (en-US).

    5.1. Cómo encontrar ayuda sobre las clases de .NET

    El curso de 2008 ofrecía una descripción detallada, con capturas de pantalla, de la ayuda de MSDN instalada con Visual Studio 2008. Esta ayuda local ya no está disponible: la documentación de .NET ahora está en línea, es gratuita y se actualiza con cada nueva versión.

    5.1.1. Documentación en línea

    El punto de partida es el sitio web de Microsoft learn.microsoft.com. Allí encontrará:

    • la documentación del lenguaje C#: https://learn.microsoft.com/en-us/dotnet/csharp/. Incluye una visión general del lenguaje, tutoriales, la referencia del lenguaje (palabras clave, operadores, instrucciones) y una sección “Novedades” que describe cada versión de C#;
    • la referencia de la API de .NET: https://learn.microsoft.com/en-us/dotnet/api/. Describe, espacio de nombres por espacio de nombres, todas las clases de .NET: sus constructores, propiedades y métodos, con ejemplos;
    • el explorador de API, en la misma página: un cuadro de búsqueda donde se puede escribir el nombre de una clase o método ([StringBuilder], [Regex.Match]…). Una lista desplegable permite seleccionar la versión de .NET (aquí, .NET 10).

    La página de una clase, como System.String, muestra:

    • el espacio de nombres de la clase y el ensamblado que la contiene;
    • su declaración, su clase padre y las interfaces que implementa;
    • una lista de sus constructores, propiedades y métodos, cada uno con un enlace a una página detallada que muestra sus diversas sobrecargas, parámetros, valores de retorno, posibles excepciones y, a menudo, un ejemplo;
    • notas sobre su uso.

    Las páginas están disponibles en francés (traducción automática) y en inglés (texto original, que a veces es más preciso). Se puede cambiar de uno a otro reemplazando [en-us] por [fr-fr] en la URL. Una búsqueda en un motor de búsqueda con el nombre completo de la clase (“System.Text.StringBuilder”) suele llevar directamente a la página correcta.

    5.1.2. Ayuda del editor

    El editor de código (Visual Studio, Visual Studio Code con la extensión C# Dev Kit, Rider) ofrece ayuda inmediata sin salir del código:

    • el autocompletado (IntelliSense): después de escribir [aString.], el editor sugiere una lista de las propiedades y métodos del objeto, junto con un resumen de cada uno;
    • Información sobre herramientas: al colocar el mouse sobre el nombre de una clase, método o variable, se muestra su declaración y un resumen de su documentación;
    • Ayuda de parámetros: al escribir el paréntesis de apertura de una llamada, el editor muestra las diferentes sobrecargas del método y la función de cada parámetro;
    • Ir a la definición (tecla F12): muestra la declaración de la clase o del método. Para una clase de .NET, el editor muestra las declaraciones públicas reconstruidas a partir del ensamblado, junto con sus comentarios de documentación;
    • En Visual Studio, al pulsar la tecla F1 sobre el nombre de una clase o método se abre la página correspondiente de la documentación en línea.

    Estos comentarios de documentación, que se ven al colocar el mouse sobre un elemento, son los que se usan para generar la referencia en línea. Se pueden escribir comentarios similares en el código propio mediante la sintaxis [/// <summary> ... </summary>] colocada encima de una clase o método: el editor los mostrará de la misma manera.

    5.2.1. La clase System.String

    Es importante observar que una cadena del tipo [string] es inmutable; no se puede modificar después de crearla. Cuando un método devuelve una cadena, esta es distinta de la cadena a la que se aplicó el método. Así, [s1.Trim()] devuelve la cadena [s2], y [s1] y [s2] son dos cadenas diferentes: [s1] no ha cambiado.

    Una cadena [c] puede considerarse un arreglo de caracteres de solo lectura:

    • [c[i]] es el i-ésimo carácter de [c] (el primer carácter es el número 0);
    • [c.Length] es el número de caracteres de [c].

string title = "Learning the C# language with .NET";

// Contains, StartsWith, EndsWith: comparación exacta por defecto

Console.WriteLine($"EndsWith('T') : {title.EndsWith('T')}");

    • Línea 32: [PadLeft] y [PadRight] rellenan una cadena hasta una longitud dada; el constructor [new string('-', 8)] repite un carácter.

static double[] Input()
{
    // al inicio, el arreglo está vacío
    double[] elements = [];
    // bucle de ingreso de los elementos del arreglo
    while (true)
    {
        Console.Write($"Element (real) {elements.Length} of the array (nothing to finish): ");
        string answer = (Console.ReadLine() ?? "").Trim();
        // fin del ingreso si la cadena está vacía
        if (answer == "")
        {
            break;
        }
        // verificación del ingreso
        if (!double.TryParse(answer, out double element))
        {
            Console.WriteLine("Incorrect input, try again");
            continue;
        }
        // un elemento más: agrandamos el arreglo en una celda
        Array.Resize(ref elements, elements.Length + 1);
        // y almacenamos en ella el nuevo elemento
        elements[^1] = element;
    }
    return elements;
}

// búsqueda en el arreglo de elementos escritos en el teclado
static void Search(double[] elements, SearchType type)
{
    while (true)
    {
        Console.Write("Element searched for (nothing to stop): ");
        string answer = (Console.ReadLine() ?? "").Trim();
        // ¿terminó?
        if (answer == "")
        {
            break;
        }
        // verificación
        if (!double.TryParse(answer, out double element))
        {
            Console.WriteLine("Error, try again...");
            continue;
        }
        // buscamos el elemento en el arreglo
        int i = type == SearchType.Binary
            ? Array.BinarySearch(elements, element)    // arreglo ordenado
            : Array.IndexOf(elements, element);        // arreglo cualquiera
        // visualización de la respuesta
        Console.WriteLine(i >= 0 ? $"Found at position {i}" : $"Not in the array ({i})");
    }
}

    5.4. Colecciones genéricas

    Además de los arreglos, existen diversas clases para almacenar colecciones de elementos. Las colecciones genéricas, introducidas con .NET 2.0, se encuentran en el espacio de nombres [System.Collections.Generic], que forma parte de los espacios de nombres [using] implícitos. Presentaremos primero dos colecciones de uso frecuente —la lista y el diccionario— y luego veremos brevemente otras.

    El espacio de nombres [System.Collections] contiene las versiones más antiguas, no genéricas, de estas colecciones, que datan de .NET 1.0: [ArrayList] (una lista), [Hashtable] (un diccionario)... El curso de 2008 todavía presentaba [ArrayList]. Estas clases están ahora obsoletas: almacenan referencias de tipo [object], lo que obliga a convertir los elementos leídos y a empaquetar (boxing) los números en objetos, con los costos asociados de memoria y tiempo. Las colecciones genéricas no tienen ninguno de estos inconvenientes: una *[List<int>] almacena sus enteros directamente en un arreglo interno *[int[]] , y el compilador verifica el tipo de los elementos agregados. [ArrayList] y [Hashtable] ya no deben usarse en código nuevo.

    5.4.1. La clase genérica List<T>

    La clase [System.Collections.Generic.List<T>] permite implementar colecciones de objetos [T] cuyo tamaño varía durante la ejecución del programa. Un objeto de tipo [List<T>] se maneja casi como un arreglo. Así, el elemento i de una lista [l] se denota [l[i]].

    Para una lista de tipo [List<T>] donde [T] es una clase, la lista almacena referencias a objetos de tipo [T], como un arreglo de objetos; si [T] es un tipo de valor ([int], [double], estructura…), los propios valores se almacenan en la lista.

    5.4.3. La clase Dictionary<TKey,TValue>

    La clase [System.Collections.Generic.Dictionary<TKey,TValue>] se usa para implementar un diccionario. Un diccionario puede concebirse como un arreglo de dos columnas:

    clave
    valor
    clave1
    valor1
    clave2
    valor2
    ...
    ...

    En la clase [Dictionary<TKey,TValue>], las claves son de tipo [TKey] y los valores son de tipo [TValue]. Las claves son únicas: no puede haber dos claves idénticas. Un diccionario de este tipo se vería así si los tipos [TKey] y [TValue] se refirieran a clases:

    El valor asociado a la clave [c] en un diccionario [d] se obtiene con la notación [d[c]]. Este valor es de lectura y escritura. Así, podemos escribir:

    1
2
3
4
5

TKey k = ...;
Dictionary<TKey, TValue> d = new();
d[k] = v;
v = d[k];

    Al escribir, [d[c] = v] agrega el par (c, v) si la clave [c] no existe, y reemplaza el valor asociado a [c] en caso contrario. Al leer, si la clave [c] no existe en el diccionario [d], la notación [d[c]] lanza una excepción [KeyNotFoundException].

    5.5. LINQ

    El curso de 2008 terminaba justo antes de LINQ, presentando sus tipos anónimos sin utilizarlos realmente. LINQ (Language Integrated Query, C# 3, 2007) es un conjunto de métodos que permiten consultar una colección tal como se consulta una base de datos: filtrar, ordenar, agrupar, calcular totales, etc. Se aplica a cualquier colección que implemente la interfaz [IEnumerable<T>]: arreglos, listas, diccionarios, conjuntos, líneas de un archivo, resultados de una expresión regular y, con Entity Framework Core (capítulo 11), tablas de bases de datos. El espacio de nombres [System.Linq] forma parte de los espacios de nombres [using] implícitos.

// la carpeta actual: es donde se buscan los archivos designados con un nombre relativo
Console.WriteLine($"Current folder: {Path.GetFileName(Environment.CurrentDirectory)}");
// el nombre del archivo puede pasarse como argumento; de lo contrario infos.txt

try
{
    // lectura 1: línea por línea
    Console.WriteLine("Reading 1----------------");
    using (var stream = new StreamReader(fileName))
    {
        string? line;
        // ReadLine devuelve null al final del archivo
        while ((line = stream.ReadLine()) != null)
        {
            Console.WriteLine(line);
        }
    } // aquí se cierra el flujo

    // lectura 2: todo el archivo de una vez, con una declaración using
    Console.WriteLine("Reading 2----------------");
    using var stream2 = new StreamReader(fileName);
    Console.Write(stream2.ReadToEnd());
    // stream2 se cerrará al final del bloque que contiene su declaración, aquí el bloque try
}
catch (FileNotFoundException e)
{
    // e.FileName es la ruta completa del archivo; solo mostramos su nombre
    Console.WriteLine($"{e.GetType().Name} : the file [{Path.GetFileName(e.FileName)}] does not exist");
}
catch (IOException e)
{
    // los demás errores de entrada-salida
    Console.WriteLine($"{e.GetType().Name} : {e.Message}");
}

// leemos un archivo de texto (text) y almacenamos su contenido en un archivo binario (binary)

if (args.Length != 3)
{
    Console.WriteLine("syntax: dotnet run files-04.cs -- text binary logs");
    return 1;
}
try
{
    // apertura del archivo de texto para lectura
    using var input = new StreamReader(args[0]);
    // apertura del archivo binario para escritura
    using var output = new BinaryWriter(new FileStream(args[1], FileMode.Create, FileAccess.Write));
    // apertura del archivo de registro para escritura
    using var logs = new StreamWriter(args[2]);
    // procesamiento del archivo de texto
    string? line;
    int lineNumber = 0, nbPersons = 0;
    while ((line = input.ReadLine()) != null)
    {
        // una línea más
        lineNumber++;
        // ¿línea vacía? la ignoramos
        if (line.Trim() == "")
        {
            continue;
        }
        // una línea name : age
        string[] fields = line.Split(':', StringSplitOptions.TrimEntries);
        // se necesitan 2 campos
        if (fields.Length != 2)
        {
            logs.WriteLine($"Line no. [{lineNumber}] of the file [{args[0]}] has an incorrect number of fields");
            continue;
        }
        // el 1.er campo no debe estar vacío
        bool error = false;
        string name = fields[0];
        if (name == "")
        {
            logs.WriteLine($"Line no. [{lineNumber}] of the file [{args[0]}] has an empty name");
            error = true;
        }
        // el segundo campo debe ser un entero >= 0
        if (!int.TryParse(fields[1], out int age) || age < 0)
        {
            logs.WriteLine($"Line no. [{lineNumber}] of the file [{args[0]}] has an incorrect age [{fields[1]}]");
            error = true;
        }
        // si no hay error, escribimos los datos en el archivo binario
        if (!error)
        {
            output.Write(name);
            output.Write(age);
            nbPersons++;
        }
    }
    Console.WriteLine($"{lineNumber} lines read, {nbPersons} persons written to [{args[1]}], errors in [{args[2]}]");
    // fin del bloque try: los tres flujos se cierran aquí, en el orden inverso al de su apertura
}
catch (FileNotFoundException e)
{
    // e.FileName es la ruta completa del archivo; solo mostramos su nombre
    Console.WriteLine($"The file [{Path.GetFileName(e.FileName)}] does not exist");
    return 2;
}
catch (IOException e)
{
    Console.WriteLine($"The following error occurred: {e.GetType().Name} : {e.Message}");
    return 3;
}

    5.7.2. La serialización JSON

    Escribir y leer un archivo binario byte por byte es tedioso, y la más mínima discrepancia entre la escritura y la lectura produce resultados incorrectos. Por lo general es preferible serializar los objetos: convertirlos automáticamente en una secuencia de bytes o de caracteres y luego deserializarlos para reconstruirlos.

    .NET proporcionaba para ello la clase [BinaryFormatter], que serializaba los objetos en un formato binario específico de .NET. Ahora ha sido eliminada: se declaró obsoleta en .NET 5 y su implementación se eliminó en .NET 9, porque deserializar datos de una fuente no confiable con [BinaryFormatter] permitía ejecutar código arbitrario. Microsoft recomienda reemplazarla por la serialización JSON de la biblioteca [System.Text.Json], integrada en .NET desde .NET Core 3.0.

    JSON (JavaScript Object Notation) es un formato basado en texto, legible por humanos y universal: es el formato de intercambio de los servicios web (capítulo 13) y de numerosos archivos de configuración. Un objeto se escribe entre llaves con pares "propiedad":valor, y las matrices se encierran entre corchetes.

    5.8. Expresiones regulares

    La clase [System.Text.RegularExpressions.Regex] permite el uso de expresiones regulares. Estas permiten validar el formato de una cadena. Por ejemplo, se puede verificar que una cadena que representa una fecha tenga efectivamente el formato dd/mm/aa. Para ello, se usa un patrón y se compara la cadena con ese patrón. En este ejemplo, d, m y a deben ser dígitos. El patrón de un formato de fecha válido es, por lo tanto, [\d\d/\d\d/\d\d], donde el símbolo [\d] representa un dígito. Los símbolos que se pueden usar en un patrón son los siguientes:

    carácter
    descripción
    [\]
    marca el carácter siguiente como carácter especial o literal. Por ejemplo, [n] corresponde al carácter n, [\n] corresponde a un carácter de nueva línea, [\\] corresponde a \ y [\(] corresponde a (
    [^]
    corresponde al inicio de la cadena
    [$]
    corresponde al final de la cadena
    [*]
    coincide con el elemento anterior cero o más veces. Así, [zo*] coincide con z o zoo
    [+]
    coincide con el elemento anterior una o más veces. Así, [zo+] coincide con "zoo", pero no con "z"
    [?]
    coincide con el elemento anterior cero o una vez. Por ejemplo, [a?ve?] coincide con “ve” en “lever”
    [.]
    coincide con cualquier carácter individual, excepto el carácter de nueva línea
    [(pattern)]
    busca el patrón y almacena la coincidencia (un grupo). La subcadena coincidente se puede extraer de la colección [Groups] del resultado. Para buscar coincidencias con caracteres entre paréntesis, use [\(] o [\)]
    [x|y]
    coincide con x o con y. Por ejemplo, [z|foot] coincide con z o foot; [(z|f)oo] coincide con zoo o foo
    [{n}]
    n es un entero no negativo. Coincide exactamente n veces con el elemento anterior. Por ejemplo, [o{2}] no coincide con la o de Bob, pero sí con las dos primeras o de fooooot
    [{n,}]
    coincide con el elemento anterior al menos n veces. Por ejemplo, [o{2,}] no coincide con la 'o' de 'Bob', pero sí con todas las 'o' de 'fooooot'. [o{1,}] equivale a [o+], y [o{0,}] equivale a [o*]
    [{n,m}]
    coincide con el elemento anterior al menos n veces y como máximo m veces. Por ejemplo, [o{1,3}] coincide con las tres primeras “o” de “foooooot”; [o{0,1}] equivale a [o?]
    [xyz]
    conjunto de caracteres: coincide con uno de los caracteres especificados. Por ejemplo, [abc] coincide con la letra “a” en “plat”
    [^xyz]
    conjunto negativo de caracteres: coincide con cualquier carácter que no esté en la lista. Por ejemplo, [^abc] coincide con "p" en "plat"
    [a-z]
    rango de caracteres: coincide con cualquier carácter del rango especificado, en este caso una letra minúscula sin acento
    [^m-z]
    rango negativo de caracteres: coincide con cualquier carácter que no esté entre 'm' y 'z'
    [\b]
    coincide con un límite de palabra, es decir, la posición entre un carácter de palabra y un carácter que no es de palabra. Por ejemplo, [er\b] coincide con "er" en "lever", pero no con "er" en "verb"
    [\B]
    corresponde a una posición que no es un límite de palabra. [en*t\B] corresponde a “ent” en “entertain”
    [\d]
    corresponde a un dígito; equivale a [0-9] (en .NET, también para los dígitos de otros alfabetos Unicode)
    [\D]
    corresponde a un carácter que no es un dígito
    [\f], [\n], [\r], [\t], [\v]
    corresponden, respectivamente, a los caracteres de salto de página, nueva línea, retorno de carro, tabulación y tabulación vertical
    [\s]
    corresponde a cualquier espacio en blanco: espacio, tabulación, salto de página, salto de línea… Equivale a [ \f\n\r\t\v], más otros caracteres de espacio en blanco de Unicode (espacio de no separación, etc.)
    [\S]
    coincide con cualquier carácter que no sea un espacio en blanco
    [\w]
    coincide con cualquier carácter de palabra: letra (con o sin acentos), dígito o guion bajo
    [\W]
    coincide con cualquier carácter que no sea un carácter de palabra
    [\num]
    num es un entero positivo: hace referencia al grupo número num. Por ejemplo, [(.)\1] coincide con dos caracteres idénticos consecutivos
    [\xnn], [\unnnn]
    corresponde al carácter hexadecimal nn (2 dígitos) o nnnn (4 dígitos). Por ejemplo, [\x41] corresponde a A

    Un elemento de un patrón puede aparecer una o varias veces. Veamos algunos ejemplos con el símbolo [\d], que representa un solo dígito:

    patrón
    Significado

    Se pueden “extraer” subconjuntos de un patrón. Así, no solo podemos verificar que una cadena coincide con un patrón determinado, sino también extraer de esa cadena los elementos que corresponden a los subconjuntos del patrón que se han encerrado entre paréntesis. Por ejemplo, si se analiza una cadena que contiene una fecha en formato dd/mm/aa y se quieren extraer también los componentes dd, mm y aa de esa fecha, se usaría el patrón [(\d\d)/(\d\d)/(\d\d)].

    En el código C#, un patrón se escribe de preferencia como una cadena textual [@"..."]: de esta manera, no es necesario duplicar los numerosos caracteres [\] de los patrones. Con una cadena normal, habría que escribir ***["\\\\d+"] en lugar de ***[@"\\d+"].

    • línea 50: el patrón [^(a+)+$] es patológico: cuando se aplica a una secuencia de “a” que termina con otro carácter, el motor de expresiones regulares prueba todas las formas posibles de distribuir las “a” entre las repeticiones del grupo antes de concluir que ha fallado. El número de posibilidades se duplica con cada “a” adicional: con 30 “a” hay aproximadamente mil millones de posibilidades. Esto se conoce como retroceso catastrófico. Un patrón así, aplicado a cadenas ingresadas por los usuarios, es una vulnerabilidad de seguridad: bastan unas pocas solicitudes para hacer caer un servidor. El parámetro [matchTimeoutMilliseconds] establece un tiempo de espera de 100 ms: transcurrido este, la búsqueda se abandona con una excepción [RegexMatchTimeoutException] (línea 6);
    • línea 35: la opción [NonBacktracking] (.NET 7) usa un motor distinto, que garantiza un tiempo de búsqueda proporcional a la longitud de la cadena. No admite ciertas construcciones (referencias hacia atrás, como [\1], por ejemplo), pero en este caso devuelve un resultado de inmediato.

    Observe que se debe establecer un tiempo de espera o usar [NonBacktracking] siempre que el patrón o la cadena en la que se busca provenga de fuera del programa.

    public int Calculate(bool married, int nbChildren, int salary)
    {
        // cálculo del número de partes
        decimal shares = (decimal)nbChildren / 2 + (married ? 2 : 1);
        if (nbChildren >= 3)
        {
            shares += 0.5m;
        }
        // cálculo del ingreso gravable y del cociente familiar
        decimal income = 0.72m * salary;
        decimal quotient = income / shares;
        // búsqueda del tramo del impuesto: se usa el último si ningún límite se ajusta
        TaxBracket[] brackets = TaxBrackets;

            if (quotient <= brackets[i].Limit)
            {
                bracket = brackets[i];
                break;
            }
        }
        // cálculo del impuesto
        return (int)(income * bracket.CoeffR - shares * bracket.CoeffN);
    }
}

using System.Text.RegularExpressions;

namespace TaxV3;

// los tramos del impuesto leídos de un archivo de texto con líneas limit:coeffR:coeffN
public partial class FileTax : AbstractTax
{
    // el separador de campos: el carácter : rodeado de espacios opcionales
    [GeneratedRegex(@"\s*:\s*")]
    private static partial Regex Separator();

    // los tramos del impuesto leídos del archivo
    private readonly TaxBracket[] taxBrackets;

    // implementación de la propiedad abstracta de la clase padre
    protected override TaxBracket[] TaxBrackets => taxBrackets;

    public FileTax(string fileName)
    {
        // el nombre del archivo, sin su ruta, para los mensajes de error
        string name = Path.GetFileName(fileName);
        // los tramos leídos; no conocemos su número de antemano
        List<TaxBracket> brackets = [];
        try
        {
            int lineNumber = 0;
            foreach (string lineRead in File.ReadLines(fileName))
            {
                lineNumber++;
                string line = lineRead.Trim();
                // las líneas vacías se ignoran
                if (line == "")
                {
                    continue;
                }
                // la línea debe tener tres campos
                string[] fields = Separator().Split(line);
                if (fields.Length != 3)
                {
                    throw new TaxException($"Line no. {lineNumber} is incorrect ({line})")
                    {
                        Code = (int)ErrorCode.Line
                    };
                }
                // tres números decimales positivos o cero, escritos con punto decimal
                ErrorCode code = 0;
                if (!Read(fields[0], out decimal limit)) code |= ErrorCode.Field1;
                if (!Read(fields[1], out decimal coeffR)) code |= ErrorCode.Field2;
                if (!Read(fields[2], out decimal coeffN)) code |= ErrorCode.Field3;
                if (code != 0)
                {
                    throw new TaxException($"Line no. {lineNumber} is incorrect ({line})")
                    {
                        Code = (int)code
                    };
                }
                // almacenamos el nuevo tramo del impuesto
                brackets.Add(new TaxBracket(limit, coeffR, coeffN));
            }
        }
        catch (Exception e) when (e is IOException or UnauthorizedAccessException)
        {
            // error de acceso al archivo: lo envolvemos en una TaxException
            throw new TaxException($"Error while reading the file {name}", e)
            {
                Code = (int)ErrorCode.Access
            };
        }
        // se necesita al menos un tramo
        if (brackets.Count == 0)
        {
            throw new TaxException($"The file {name} does not contain any bracket")
            {
                Code = (int)ErrorCode.Line
            };
        }
        // transferimos la lista al arreglo de tramos
        taxBrackets = brackets.ToArray();
    }

    // conversión de un campo a decimal >= 0, sin importar la cultura de la máquina
    private static bool Read(string field, out decimal result) =>
        decimal.TryParse(field, NumberStyles.AllowDecimalPoint, CultureInfo.InvariantCulture, out result);
}

    Comentarios:

    • línea 7: la clase [FileTax] deriva de la clase [AbstractTax], al igual que la clase [HardwiredTax] en la versión 2. Se declara como [partial] porque contiene una expresión regular generada;
    • líneas 10–11: la expresión regular del separador de campos en una línea limit:coeffR:coeffN: el carácter [:], precedido y seguido de cualquier cantidad de espacios;
    • líneas 14–17: los tramos leídos, devueltos por la propiedad [TaxBrackets], que redefine la propiedad abstracta de [AbstractTax];
    • línea 19: el constructor recibe el nombre del archivo de texto que contiene los datos. Su función es llenar la matriz [taxBrackets];
    • línea 22: el nombre del archivo sin su ruta, que se usa en los mensajes de error. En realidad, el constructor recibe una ruta completa, que no es necesario mostrar al usuario;
    • línea 24: la lectura de un archivo de texto es secuencial: el número de líneas no se conoce hasta haber leído todo el archivo. Por lo tanto, no se puede dimensionar la matriz de antemano; los tramos se almacenan temporalmente en una lista;
    • línea 28: el archivo se lee línea por línea con [File.ReadLines], que abre y cierra el archivo por sí mismo. El curso de 2008 usaba [StreamReader];
    • líneas 38–43: la línea se divide en campos mediante una expresión regular; si no hay tres campos, se lanza una excepción [TaxException] con el código [Line] . El curso de 2008 guardaba el error en una variable, salía del bucle y lanzaba la excepción después de cerrar el archivo: lanzarla de inmediato es más simple, y [File.ReadLines] cierra el archivo en cualquier caso, ya que el bucle [foreach] libera su enumerador incluso cuando una excepción lo interrumpe;
    • líneas 47–55: conversión de los tres campos a números decimales. Los errores se acumulan en la variable [code] mediante el operador [|=] y luego se informan juntos;
    • líneas 83–84: conversión de un campo. [NumberStyles.AllowDecimalPoint] solo permite dígitos y un punto decimal: sin signos, espacios ni separadores de miles. Por lo tanto, los números negativos se rechazan, lo que valida los datos al mismo tiempo que se convierten. [CultureInfo.InvariantCulture] impone el punto como separador decimal, sea cual sea la configuración regional de la máquina;
    • líneas 62–67: los errores de acceso al archivo ([IOException] y sus variantes, como [FileNotFoundException], o [UnauthorizedAccessException] por permisos insuficientes) se encapsulan en una [TaxException] con el código [Access]. El [when (...)] filtro de excepciones (C# 6) intercepta solo estas excepciones: las excepciones [TaxException] lanzadas dentro del bucle no se interceptan y salen del constructor sin cambios. El patrón [e is IOException or UnauthorizedAccessException] es un patrón combinado que usa [or] (C# 9);
    • líneas 71–79: un archivo vacío se rechaza; de lo contrario, la lista se transfiere a la matriz de tramos, que era el objetivo del constructor.

    Encapsular las excepciones de bajo nivel ([IOException]) en una excepción específica de la aplicación ([TaxException]) permite que el código que llama maneje un solo tipo de excepción, sea cual sea la fuente de datos: un archivo de texto, un archivo JSON y, más adelante en el curso, una base de datos.

public class JsonTax : AbstractTax

    public JsonTax(string fileName)
    {
        // el nombre del archivo, sin su ruta, para los mensajes de error
        string name = Path.GetFileName(fileName);
        string json;
        try
        {
            // lectura del archivo
            json = File.ReadAllText(fileName);
        }
        catch (Exception e) when (e is IOException or UnauthorizedAccessException)
        {
            throw new TaxException($"Error while reading the file {name}", e)
            {
                Code = (int)ErrorCode.Access
            };
        }
        TaxBracket[]? brackets;
        try
        {
            // deserialización del arreglo de tramos
            brackets = JsonSerializer.Deserialize<TaxBracket[]>(json, options);
        }
        catch (JsonException e)
        {
            throw new TaxException($"The file {name} is incorrect: {e.Message}", e)
            {
                Code = (int)ErrorCode.Json
            };
        }
        // se necesita al menos un tramo, sin ningún valor negativo
        if (brackets is null || brackets.Length == 0)
        {
            throw new TaxException($"The file {name} does not contain any bracket")
            {
                Code = (int)ErrorCode.Json
            };
        }
        if (brackets.Any(t => t.Limit < 0 || t.CoeffR < 0 || t.CoeffN < 0))
        {
            throw new TaxException($"The file {name} contains a negative value")
            {
                Code = (int)ErrorCode.Json
            };
        }
        taxBrackets = brackets;
    }
}

    • línea 9: las opciones “Web”: las propiedades JSON [limit], [coeffR] y [coeffN] corresponden a las propiedades [Limit], [CoeffR] y [CoeffN] de la estructura [TaxBracket] sin necesidad de modificar esta última con atributos.     • líneas 25–31: lectura del archivo; un error de acceso se maneja como en [FileTax];
    • línea 38: una sola instrucción convierte el texto JSON en una matriz de tramos. [System.Text.Json] sabe construir una estructura de tipo registro llamando a su constructor. Un documento no válido provoca una [JsonException], encapsulada dentro de una [TaxException] con el código [Json];

    5.10. Conclusión

    Este capítulo ha presentado las clases de .NET que se usan en casi todos los programas:

    • las cadenas inmutables ([string]) y las cadenas mutables ([StringBuilder]) para construirlas pieza por pieza; la interpolación con anchos y formatos, las cadenas sin formato (raw); las vistas ([ReadOnlySpan<char>]) para el código crítico;
    • las matrices y la clase [Array];
    • las colecciones genéricas [List<T>], [Dictionary<TKey,TValue>], [HashSet<T>], [Queue<T>], [Stack<T>], [PriorityQueue<TElement,TPriority>] y sus interfaces de solo lectura; las colecciones no genéricas [ArrayList] y [Hashtable] están obsoletas;
    • LINQ, sus secuencias [IEnumerable<T>], sus iteradores y su ejecución diferida;

    • las expresiones regulares, preferentemente generadas en tiempo de compilación y siempre protegidas por un tiempo de espera al procesar datos externos.
