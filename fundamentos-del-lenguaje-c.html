    3. Fundamentos del lenguaje C#

    3.1. Introducción

    Comenzaremos tratando C# como un lenguaje de programación tradicional. Las clases se abordarán en el siguiente capítulo. En un programa hay dos componentes principales:

    • los datos;
    • las instrucciones que los manipulan.

    Por lo general, se procura separar los datos de las instrucciones:

    Todos los ejemplos de este capítulo son aplicaciones de un solo archivo: un único archivo [.cs], sin archivo de proyecto ([.csproj]), que se ejecuta con el comando [dotnet run basics-01.cs]. Esta característica, introducida con .NET 10, se trató en el capítulo anterior. Los ejemplos se encuentran en la carpeta [03-basics] del código del curso. Se ejecutan con la configuración regional francesa (fr-FR), como en una máquina Windows en francés: los números reales se muestran con coma decimal.

    • línea 5: la clase [Console] pertenece al espacio de nombres [System]. Su nombre completo es [System.Console]. Un espacio de nombres agrupa tipos relacionados, del mismo modo que una carpeta agrupa archivos;

    • Línea 4: la clase se coloca en el espacio de nombres [Basics]. Esta es la forma que utilizaremos de ahora en adelante;
    • Línea 6: en C#, todo el código pertenece a una clase. Aquí la clase se llama [Program];
    • Línea 9: el método estático [Main] es el punto de entrada del programa: es el método que el sistema ejecuta al iniciarlo. Su parámetro, [args], recibe los argumentos de la línea de comandos.

    Los dos programas son equivalentes. Cuando encuentra instrucciones de nivel superior, el compilador genera una clase y un método llamado [Main] que contienen esas instrucciones, así como el parámetro [string[] args]. Las instrucciones de nivel superior son, por tanto, una simple forma abreviada de la sintaxis estándar. Resultan adecuadas para los programas pequeños de este capítulo; la sintaxis estándar sigue siendo útil cuando se quiere inspeccionar la clase que contiene [Main].

    Más arriba hemos enumerado los tipos .NET equivalentes a cada tipo de C#, marcados con (S) si el tipo es una estructura y con (C) si es una clase. Vemos que existen dos nombres posibles para un entero de 32 bits: [int] e [Int32]. El tipo [int] es una palabra clave de C#. [Int32] es una estructura que pertenece al espacio de nombres [System]: su nombre completo es [System.Int32]. El tipo [int] es un alias de C# que designa la estructura .NET [System.Int32]. Del mismo modo, el tipo C# [string] es un alias del tipo .NET [System.String]. [System.String] es una clase, no una estructura. Los dos conceptos son similares, pero con la siguiente diferencia fundamental:

    • una variable de tipo estructura contiene directamente su valor: se denomina tipo de valor;
    • una variable de un tipo clase contiene la dirección del objeto (su referencia); se denomina tipo de referencia.

    Además, existen dos tipos menos comunes:

    • [nint] y [nuint] (C# 9) son enteros con y sin signo cuyo tamaño es el de una dirección de memoria: 4 bytes en un sistema de 32 bits, 8 bytes en un sistema de 64 bits. Se utilizan principalmente para interactuar con código nativo;
    • [System.Half] (.NET 5) es un número de punto flotante de 2 bytes y baja precisión, utilizado en gráficos por computadora y en aprendizaje automático. No es un tipo predefinido del lenguaje: no tiene una palabra clave de C#.

    Una estructura, al igual que una clase, es un tipo complejo con propiedades y métodos. Así, podemos escribir:

    1
    string? typeName = 3.GetType().FullName;

    El literal 3 es, de forma predeterminada, de tipo C# [int], y por tanto de tipo .NET [System.Int32]. Esta estructura tiene un método [GetType()] que devuelve un objeto que describe el tipo de dato. Entre las propiedades de este objeto, [FullName] es el nombre completo del tipo. El literal 3 es, pues, un objeto más complejo de lo que parece a primera vista. El signo de interrogación de [string?] se explicará un poco más adelante.

    En el código fuente, los números de punto flotante siempre se escriben con punto decimal, sea cual sea la configuración regional del sistema. Desde C# 7, los enteros pueden escribirse en binario (con el prefijo [0b]) y los grupos de dígitos pueden separarse con el carácter _ para mejorar la legibilidad: [1_000_000] es el entero un millón.

    Un literal de cadena estándar puede contener secuencias de escape introducidas por el carácter \: "\n" representa el carácter de fin de línea y no la secuencia de los dos caracteres \ y n, "\t" representa una tabulación, "\"" representa unas comillas dobles y "\\" representa el propio carácter \. Para escribir la ruta de Windows c:\chap1\paragraph3, hay que escribir, por tanto, "c:\\chap1\\paragraph3". También se puede escribir @"c:\chap1\paragraph3": la sintaxis @"texto" indica que el texto debe tomarse exactamente tal como está escrito, sin interpretar el carácter \. Esto se denomina cadena textual.

    C# ofrece ahora otros dos tipos de cadenas:

    • la cadena interpolada (C# 6) $"...": las expresiones entre llaves se evalúan y sus valores se insertan en la cadena. Una expresión puede ir seguida de un especificador de formato después de los dos puntos: [$"{d1:F2}"] muestra el número de punto flotante [d1] con dos decimales. Es la forma más legible de construir una cadena, y la utilizaremos de ahora en adelante en lugar de los formatos {0}, {1}, ...;
    • La cadena literal sin formato (C# 11) """...""" : comienza y termina con al menos tres comillas. Puede contener comillas y caracteres \ sin escapar, y puede ocupar varias líneas. Los espacios que preceden a las comillas de cierre se eliminan de cada línea, lo que permite sangrar el texto junto con el código. Es muy útil para escribir JSON, SQL o HTML.

    3.3.3. Declaración de datos

    3.3.3.1. Función de las declaraciones

    Un programa manipula datos caracterizados por un nombre y un tipo. Estos datos se almacenan en la memoria. Cuando se compila el programa, el compilador asigna a cada dato una ubicación de memoria caracterizada por una dirección y un tamaño. Lo hace a partir de las declaraciones realizadas por el programador. Además, estas declaraciones permiten al compilador detectar errores de programación. Así, la operación [x = x * 2;] se declarará no válida si [x] es una cadena de caracteres.

    3.3.3.2. Declaración de constantes

    La sintaxis para declarar una constante es la siguiente:

    1
    const type name = value;

    Por ejemplo:

    1
    const double VatRate = 0.2;

    ¿Por qué declarar constantes?

    • El programa es más fácil de leer si la constante tiene un nombre significativo;
    • es más fácil modificar el programa si hay que cambiar la “constante”. Así, si la tasa de IVA pasa a 0,25, la única modificación necesaria será en la instrucción que define su valor: [const double VatRate = 0.25;]. Si se hubiera utilizado 0,2 de forma explícita en el programa, habría que modificar numerosas instrucciones.

    El valor de una constante debe conocerse en tiempo de compilación: un número, una cadena, un booleano o una expresión que pueda calcularse a partir de otras constantes. Por convención, en .NET los nombres de las constantes comienzan con mayúscula.

    3.3.3.3. Declaración de variables

    Una variable se identifica por un nombre y se asocia a un tipo de datos. C# distingue entre mayúsculas y minúsculas: las variables [END] y [end] son diferentes.

    Las variables pueden inicializarse al declararse. La sintaxis para declarar una o varias variables es:

    1
    type variable1 = value1, variable2 = value2, ...;

    donde [type] es un tipo predefinido o un tipo definido por el programador. La inicialización es opcional; sin embargo, C# no permite el uso de una variable local a la que aún no se le ha asignado un valor.

    También se puede omitir el tipo de una variable usando la palabra clave [var] en lugar del tipo:

    1
    var variable1 = value1;

    La palabra clave [var] no significa que la variable carezca de un tipo específico: tiene el tipo del valor que se le asigna, determinado por el compilador. Aquí la inicialización es obligatoria para que el compilador pueda deducir el tipo. Utilizamos [var] cuando el tipo se deduce con claridad del valor.

    3.3.4. Tipos que admiten valores NULL

    Una variable de un tipo de valor, como [int], siempre contiene un valor. A veces resulta útil poder expresar la ausencia de valor: una edad desconocida, un campo vacío en una base de datos. El tipo [int?] (C# 2) es el tipo [int] al que se le agrega el valor [null], que significa “sin valor”. Se habla entonces de tipo de valor que admite valores NULL. El principio se aplica a todos los tipos de valor: [double?], [bool?], [DateTime?], ...

    Una variable de un tipo de referencia, como [string], siempre puede tener el valor [null]: esto significa que no hace referencia a ningún objeto. Intentar utilizar un miembro de una variable de este tipo (por ejemplo, su propiedad [Length]) provocará un error en tiempo de ejecución ([NullReferenceException]), uno de los errores más comunes en C#. Desde C# 8, el compilador puede ayudar a evitarlo: con los tipos de referencia que admiten valores NULL, habilitados de forma predeterminada en los proyectos creados con el comando [dotnet new] y en las aplicaciones de un solo archivo,

    • el tipo [string] designa una cadena que nunca vale [null];
    • el tipo [string?] designa una cadena que puede ser [null].

    El compilador rastrea los valores posibles de las variables y emite una advertencia cuando existe el riesgo de utilizar el valor [null]: asignar [null] a una variable [string], utilizar [Length] en una variable [string?] que no se ha comprobado, etc. A diferencia de [int?], [string?] no crea un nuevo tipo en tiempo de ejecución: es una indicación destinada al compilador.

    3.3.6. Arreglos de datos

    Un arreglo de C# es un objeto que permite agrupar datos del mismo tipo bajo un único identificador. Se declara así:

    1
    Type[] array = new Type[n];

    [n] es el número de elementos de datos que puede contener el arreglo. La sintaxis [array[i]] hace referencia al elemento de datos número i, donde i pertenece al intervalo [0, n-1]. Cualquier referencia al elemento [array[i]] con i fuera del intervalo [0, n-1] provoca una excepción. Al crearse, a cada elemento del arreglo se le asigna el valor predeterminado de su tipo: 0 para los números, [false] para los booleanos y [null] para los tipos de referencia. Un arreglo puede inicializarse al mismo tiempo que se declara:

    1
    int[] integers = new int[] { 0, 10, 20, 30 };

    o, de forma más sencilla:

    1
    int[] integers = { 0, 10, 20, 30 };

    o, desde C# 12, mediante una expresión de colección:

    1
    int[] integers = [0, 10, 20, 30];

    De ahora en adelante utilizaremos esta última forma. Los arreglos tienen una propiedad [Length], que representa el número de elementos que contienen.

    Un arreglo bidimensional se declara así:

    1
    Type[,] array = new Type[n, m];

    donde [n] es el número de filas y [m] es el número de columnas. La sintaxis [array[i, j]] hace referencia al elemento j de la fila i. El arreglo bidimensional también puede inicializarse al mismo tiempo que se declara:

    1
    double[,] reals = { { 0.5, 1.7 }, { 8.4, -6 } };

    El número de elementos de cada dimensión se obtiene con el método [GetLength(i)], donde i=0 representa la dimensión correspondiente al primer índice, i=1 la dimensión correspondiente al segundo índice, y así sucesivamente. El número de dimensiones se obtiene con la propiedad [Rank] y el número total de elementos con la propiedad [Length].

    Un arreglo de arreglos (también llamado arreglo escalonado) se declara así:

    1
    Type[][] array = new Type[n][];

    La declaración anterior crea un arreglo de n elementos. Cada elemento, [array[i]], es una referencia a un arreglo unidimensional. Estas referencias no se inicializan con la declaración anterior; tienen el valor [null]. A diferencia de un arreglo bidimensional, cada fila puede tener una longitud distinta.

    3.4.5. Asignación del valor de una expresión a una variable

    Aquí nos interesa la operación [variable = expression;]. La expresión puede ser aritmética, relacional, booleana, de cadena, etc.

    3.4.5.1. Interpretación de la operación de asignación

    La operación [variable = expression;] es en sí misma una expresión que se evalúa de la siguiente manera:

    • se evalúa el lado derecho de la asignación: el resultado es un valor V;
    • el valor V se asigna a la variable;
    • el valor V es también el valor de la asignación, considerada ahora como una expresión.

    Así, la operación [V1 = V2 = expression] es válida. Como el operador = se evalúa de derecha a izquierda, se obtiene [V1 = (V2 = expression)]. Se evalúa la expresión [V2 = expression] y esta tiene el valor V. Su evaluación provocó que V se asignara a V2. A continuación, el siguiente operador = se evalúa como [V1 = V]. El valor de esta expresión sigue siendo V; su evaluación hace que V se asigne a V1. Así, la operación [V1 = V2 = expression] es una expresión cuya evaluación:

    • hace que el valor de [expression] se asigne a las variables V1 y V2;
    • devuelve el valor de [expression].

    Esto se puede generalizar a una expresión de la forma [V1 = V2 = ... = Vn = expression].

    El orden de las operaciones al evaluar una expresión aritmética es el siguiente (de mayor a menor prioridad):

    1
    [functions], [( )], [*, /, %], [+, -]

    Los operadores dentro de un mismo bloque [ ] tienen la misma precedencia. Cuando la precedencia es igual, la evaluación se realiza de izquierda a derecha: 10 - 4 - 3 se evalúa como (10 - 4) - 3 = 3.

    Comparación de dos cadenas

    Se comparan carácter por carácter. La primera desigualdad encontrada entre dos caracteres produce una desigualdad en el mismo sentido entre las cadenas. Consideremos la comparación de las cadenas "Cart" y "Cat":

    Funciones para comparar dos cadenas

    Se pueden usar los operadores relacionales == y != para comprobar si dos cadenas son iguales, o el método [Equals] de la clase [System.String]. Para las relaciones <, <=, > y >=, los operadores no se aplican a las cadenas: hay que usar el método [CompareTo] de la clase [System.String] o el método estático [string.Compare]. Estos devuelven un entero:

    • cero si las dos cadenas son iguales;
    • positivo si la cadena n.º 1 es mayor que la cadena n.º 2;
    • negativo si la cadena n.º 1 es menor que la cadena n.º 2.

    Hay una sutileza: [CompareTo] y [string.Compare] no se limitan a comparar códigos Unicode.     • [StringComparison.Ordinal]: comparación carácter por carácter de los códigos Unicode. Es la comparación más rápida y debe usarse para identificadores, palabras clave y nombres de archivo;
    • [StringComparison.OrdinalIgnoreCase]: igual que la anterior, pero ignorando las mayúsculas y minúsculas;
    • [StringComparison.CurrentCulture] (el valor predeterminado de [CompareTo]): sigue las convenciones culturales habituales para ordenar texto destinado a los usuarios.

    3.4.5.7. Combinación de operadores

    [a = a + b] se puede escribir como [a += b]; [a = a - b] se puede escribir como [a -= b]. Lo mismo se aplica a los operadores /, %, *, <<, >>, >>>, &, |, ^. Así, [a = a / 2;] se puede escribir como [a /= 2;].

    3.4.5.8. Operadores de incremento y decremento

    La notación [variable++] significa [variable = variable + 1] o [variable += 1]. La notación [variable--] significa [variable = variable - 1] o [variable -= 1]. Cuando se usan en una expresión, estos operadores tienen dos formas:

    • [i++] (posfija): el valor de la expresión es el valor de i antes del incremento;
    • [++i] (prefija): el valor de la expresión es el valor de i después del incremento.

    3.4.5.9. El operador ternario ?:

    La expresión [expr_cond ? expr1 : expr2] se evalúa de la siguiente manera:

    • Se evalúa la expresión [expr_cond] . Esta es una expresión booleana;
    • si es verdadera, el valor de la expresión es el de [expr1] y [expr2] no se evalúa;
    • si es falsa, ocurre lo contrario: el valor de la expresión es el de [expr2] y [expr1] no se evalúa.

    La operación [i = (j > 4 ? j + 1 : j - 1);] asignará j+1 a la variable i si j > 4, y j-1 en caso contrario. Es lo mismo que escribir [if (j > 4) i = j + 1; else i = j - 1;], pero más conciso.

    3.4.5.10. Los operadores ??, ??= y ?.

    • [a?.Member] (C# 6) es [null] si a es [null] y, en caso contrario, [a.Member]. Así, [text?.Length] no provoca un error cuando [text] es igual a [null]; el resultado es de tipo [int?].

    3.4.5.12. Conversión de tipos

    En una expresión, es posible cambiar temporalmente la representación de un valor. Esto se denomina “conversión de tipos” (type casting). La sintaxis para cambiar el tipo de un valor en una expresión es la siguiente:

    1
    (type) value

    El valor adopta entonces el tipo especificado. Esto produce un cambio en la representación del valor. Se distinguen:

    • Las conversiones implícitas, que realiza automáticamente el compilador cuando no implican ninguna pérdida de información: de un [int] a un [long], de un [int] a un [double], de un [char] a un [int], etc. La conversión de un [long] a un [double] también es implícita, aunque puede perder precisión más allá de 2⁵³;
    • Las conversiones explícitas, que pueden producir una pérdida de información y que el programador debe solicitar explícitamente mediante la notación (tipo): de un [double] a un [int] (se pierde la parte decimal), de un [long] a un [int] (se pierden los bits más significativos), etc.

    3.5. Instrucciones de control de flujo del programa

    3.5.1. Detención

    El método [Exit] de la clase [Environment] permite detener la ejecución de un programa:

    1
    Environment.Exit(int status);

    [Exit] finaliza el proceso actual y devuelve el control al proceso que lo llamó, que normalmente es el intérprete de comandos.     3.8. Argumentos del programa principal

    1

    1

    3.9. Enumeraciones

    Una enumeración es un tipo de datos cuyo dominio de valores consiste en un conjunto de constantes enteras con nombre. Consideremos un programa que debe manejar las calificaciones de un examen. Hay cinco calificaciones posibles: Pass, FairlyGood, Good, VeryGood y Excellent. Podemos entonces definir una enumeración para estas cinco constantes:

    1
    enum Honours { Pass, FairlyGood, Good, VeryGood, Excellent }

    Internamente, estas cinco constantes se codifican como enteros consecutivos que empiezan en 0 para la primera constante, 1 para la siguiente, y así sucesivamente. También podemos fijar estos valores explícitamente: [enum Honours { Pass = 10, FairlyGood = 12, ... }]. Se puede declarar una variable para que tome sus valores de la enumeración:

    1
    Honours myHonours = Honours.Pass;

    Una variable se puede comparar con los distintos valores posibles de la enumeración:

    1
2
3
4
    if (myHonours == Honours.Pass)
{
    Console.WriteLine("Could do better");
}

    Así como el tipo simple [int] equivale a la estructura [System.Int32], toda enumeración deriva de la clase [System.Enum]. Esta clase tiene métodos estáticos que permiten obtener los valores y los nombres de un tipo enumerado:

    • [Enum.GetValues<Honours>()] (.NET 5) devuelve el arreglo de valores de la enumeración [Honours];
    • [Enum.GetNames<Honours>()] devuelve el arreglo de sus nombres;
    • [Enum.TryParse(str, out Honours m)] convierte una cadena en un valor de la enumeración.

    El curso de 2008 describía [Enum.GetValues(typeof(Honours))]: esta forma, que sigue siendo válida, devuelve un arreglo sin tipo que luego hay que convertir. La forma genérica [GetValues<Honours>()] devuelve directamente un arreglo de tipo [Honours[]].

    3.10. Paso de parámetros a una función

    Aquí nos centramos en cómo se pasan los parámetros a una función. Consideremos la siguiente función:

    En la definición de la función, en la línea 1, [a] se denomina parámetro formal. Se incluye únicamente para definir la función [ChangeInt]. Podría haberse llamado igualmente [b]. Consideremos ahora un ejemplo de uso de esta función:

    1
2
3

    Aquí, en la instrucción de la línea 2, [age] es el parámetro real que pasará su valor al parámetro formal [a]. Nos interesa cómo un parámetro formal obtiene el valor de un parámetro real.

    3.10.1. Modos de paso

    C# admite los siguientes modos de paso:

    • por valor (el modo predeterminado): el valor del parámetro real se copia en el parámetro formal correspondiente. Son dos entidades distintas: si la función modifica el parámetro formal, el parámetro real permanece sin cambios. Este modo es adecuado para los parámetros de entrada de una función;
    • por referencia con [ref]: el parámetro real y el parámetro formal son una misma entidad. Si la función modifica el parámetro formal, el parámetro real también se modifica. La palabra clave [ref] debe aparecer tanto en la definición de la función como en la llamada. El parámetro real debe tener un valor antes de la llamada. Este modo es adecuado para los parámetros de entrada y salida;
    • por referencia con [out]: igual que [ref], pero el parámetro es solo de salida: el parámetro real no necesita un valor inicial y la función debe asignar un valor al parámetro formal. Este es el modo que usan los métodos [TryParse]. A partir de C# 7, la variable se puede declarar en la llamada: [out var x] o [out int x];
    • por referencia de solo lectura con [in] (C# 7.2): el parámetro se pasa por referencia, lo que evita la copia, pero la función no puede modificarlo. Este modo solo es útil para estructuras grandes; para los tipos predefinidos, el paso por valor es igual de eficiente.

    3.10.2. Parámetros opcionales, argumentos con nombre, número variable de parámetros

    C# 4 introdujo los parámetros opcionales: a un parámetro se le puede dar un valor predeterminado en la definición de la función; el llamador puede entonces omitirlo. Los parámetros opcionales se colocan después de los parámetros obligatorios. También introdujo los argumentos con nombre: al llamar a la función, un parámetro real puede ir precedido del nombre del parámetro formal seguido de dos puntos. Esto permite omitir un parámetro opcional que precede a otros parámetros, o proporcionar los parámetros en cualquier orden.

    La palabra clave [params] permite escribir una función con un número variable de parámetros: el último parámetro formal es un arreglo, y el llamador puede pasar un arreglo o una lista de valores (que puede estar vacía), que el compilador organiza en un arreglo. A partir de C# 13, el parámetro [params] también puede ser de otro tipo de colección, como [List<T>] o [ReadOnlySpan<T>].

    3.11. Funciones locales y tuplas

    3.11.1. Funciones locales

    Una función local (C# 7) es una función definida dentro de un método o, como en nuestros ejemplos, entre instrucciones de nivel superior. Solo puede usarse en ese lugar. Como nuestros programas ya no tienen clases, las funciones locales reemplazan a los métodos estáticos de los ejemplos de 2008. Una función local:

    • puede llamarse antes de ser definida;
    • puede usar las variables locales que la rodean, a menos que se declare como [static]: la palabra clave [static] (C# 8) garantiza que dependa únicamente de sus parámetros, lo que facilita su comprensión. Declaramos nuestras funciones locales [static] siempre que es posible;
    • puede tener un cuerpo de expresión: [static int Square(int x) => x * x;] equivale a un cuerpo como [{ return x * x; }].

    En un programa más grande, escribimos clases y métodos: este es el tema del próximo capítulo.

    3.11.2. Tuplas

    Una tupla (C# 7) agrupa varios valores, que pueden ser de tipos distintos, en una sola entidad. El tipo [(int, string)] designa un par formado por un entero y una cadena; sus elementos se llaman [Item1] y [Item2]. Se les puede dar nombre: [(int Number, string Name)]. Una tupla se puede deconstruir: [var (number, name) = t;] asigna sus elementos a dos variables.

    Las tuplas permiten que una función devuelva varios valores sin usar parámetros [out]: esto suele ser más legible.

static (int Min, int Max) MinMax(int[] values)
{
    int min = values[0], max = values[0];
    foreach (int v in values)
    {
        if (v < min) min = v;
        if (v > max) max = v;
    }
    return (min, max);
}
